# Brief: v0.2 — Game skeleton

## Goal
The whole game flow works end to end with placeholder screens: Ready → doors open → Loading → 12 rounds → Calculating → Score. Every click is recorded with raw data. No real scoring, art or animation polish yet; this version is about structure that later versions plug into.

## Build

### 1. State machine (`src/core/state.ts`)
- States: `intro`, `ready`, `opening`, `loading`, `round`, `calculating`, `score`.
- Allowed transitions are listed explicitly. An illegal transition throws an error in dev and is ignored in production.
- `intro` exists but is skipped for now (goes straight to `ready`). It will be built in v1.4.

### 2. Scene manager (`src/core/scenes.ts` + `src/scenes/`)
- One module per state, each with `enter()` and `exit()`. Scenes render into `screen-content` (or the HUD where it makes sense).
- Placeholder content per scene:
  - **ready:** Start button. Respect `startMode` from config: `"button"` waits for a click; `"auto"` continues after `autoStartDelayMs`.
  - **opening:** doors slide apart with a plain CSS transition (duration in config). No easing polish yet.
  - **loading:** "Initializing" text + a simple progress bar that fills over `loadingMs`.
  - **round:** see section 5.
  - **calculating:** "Calculating" text for `calculatingMs`.
  - **score:** shows the raw results as a readable table (round, click x/y, latency) plus a "Play again" button that returns to `ready` with the doors closed.

### 3. Event bus (`src/core/events.ts`)
- Typed: a single map of event name → payload type. Emitting an unknown event or the wrong payload is a type error.
- Emit at least: `state.change`, `door.open.start`, `door.open.end`, `round.start`, `round.click`, `round.logged`, `round.end`, `game.end`, `score.reveal`.
- Nothing listens yet except the debug panel.

### 4. Config
- `src/config/game.config.ts`: `startMode`, `autoStartDelayMs`, door/loading/calculating durations, `roundCount` (12), `nextRoundDelayMs`.
- `src/config/rounds.config.ts`: an array of 12 round objects. For now all identical except `id`, and round 1 has `timeWeight: 0`. Type:
  ```ts
  type RoundConfig = {
    id: number;               // 1–12
    phase: 1 | 2 | 3 | 4;
    shape: { type: 'rect'; width: number; height: number; rotationDeg: number };
    offset: { x: number; y: number };   // from screen-content center, design px
    opticalOffsetY: number;   // fraction of shape height, default 0.05
    timeWeight: number;       // 0–1
    timeLimitMs: number | null;
    effects: string[];        // effect ids, empty for now
    copyKey: string;          // key into copy.ts
  };
  ```
  Phases follow the game design: rounds 1–3 phase 1, 4–7 phase 2, 8–11 phase 3, 12 phase 4.
- `src/config/copy.ts`: every visible string (button labels, objective text, scene titles), keyed. No strings hard-coded in scenes.

### 5. Round scene + input
- Shows the counter ("Test 01/12"), a progress bar, a live timer (ms since round start), the shape (a 200 × 200 placeholder rectangle), and the objective text, laid out like the Figma "Round" frame.
- One click per round, converted with `toStageCoords` and then into **shape-local coordinates** (relative to the shape's computed center, accounting for offset and rotation). Clicks outside the shape count; only one click is accepted.
- After the click: show a small "Sample 0X, logged" placeholder tooltip next to the click with x, y and time, wait `nextRoundDelayMs`, and go to the next round.
- `src/rounds/geometry.ts`: pure functions for the computed center C and optical center O of a shape config, with unit tests.
- Store results in a game session object: `{ roundId, click: {x, y}, latencyMs, C, O }[]`. Scoring math is v1.0 and is not part of this brief.

### 6. Seeded random (`src/core/rng.ts`)
- A small seeded RNG (for example mulberry32), seed from `?seed=` or random. Nothing uses it yet; it's for round variation later. Unit test that the same seed gives the same sequence.

### 7. Debug panel (extend the backtick overlay)
- Current state and round, plus the last 10 events.
- Buttons: jump to any state, jump to round N, restart.
- Toggle: show the C (cross) and O (circle) markers on the shape.
- URL params for reviewing: `?debug=1` opens the panel, `?state=round&round=5` starts there, `?seed=123`.

## Git and deploy
- Work on branch `feat/v0.2-skeleton`. Commit in small steps.
- Push the branch and open a Pull Request into `main` (use `gh pr create` if GitHub CLI is set up, otherwise tell the owner how to open it on github.com).
- Give the owner the Vercel preview link for the branch. **Do not merge.** The owner merges after review, then you set `package.json` version `0.2.0` and tag `v0.2.0` on `main`.

## Done when
- A full game from Start to Score and back to Ready works with only clicks, no console errors.
- `?state=round&round=7` opens directly on round 7; the debug panel can jump anywhere.
- The C and O markers sit where the geometry tests say, including for a rotated test shape.
- All tests, lint and build pass. The version label shows `v0.2`.

## Out of scope
Scoring formula, verdict, real visuals, alerts or round effects, sound, loading of real assets.
