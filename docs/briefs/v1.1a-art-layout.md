# Brief: v1.1a — Responsive layout system and art in place

## Goal
Replace the fixed 1440 × 900 scaled stage with a layout anchored to the viewport and to the frame image. Put the real art into every layer. Gameplay must behave exactly as in v1.0.

Update the "The stage" and "Layer stack" sections of `CLAUDE.md` when done.

## 1. Layout model

Three groups, each sized differently:

**A. Viewport HUD: fixed CSS px, never scaled**
- Logo: horizontally centered, `top: 24px`.
- Version label: horizontally centered, `bottom: 32px`.
- About link (when it exists) follows the same rule.

**B. Background: covers the viewport**
- Fills the viewport, plus an overscan of `bgOverscan` (default 12% per side) for parallax, rotation and distortion later. It must never show an edge.
- The WebGL breathing canvas follows the same box.

**C. The frame unit: frame, glow, shadows, screen, doors, screen content, screen HUD**
- One element (`.unit`) whose aspect ratio is taken from the frame PNG's intrinsic size (read at load, not hard-coded).
- Sized to the largest box that fits inside the viewport with **64px top and bottom** and **at least 24px left and right**, centered both ways:
  ```css
  .unit {
    position: absolute; left: 50%; top: 50%; translate: -50% -50%;
    aspect-ratio: var(--frame-ar);
    height: min(calc(100vh - 128px), calc((100vw - 48px) / var(--frame-ar)));
    container-type: size;
  }
  ```
- Cap the height at `maxUnitHeightPx` (set to the frame PNG's 1× height × 2), so the art never upscales past its 2× source.
- Everything inside the unit is positioned in **percentages of the unit** and sized with **container units** (`cqw`/`cqh`). Nothing inside uses viewport units or fixed px.
- Transforms (the round 10 drop, glitch, shake) apply to `.unit` as a whole, so the inner layout stays intact.

## 2. The screen opening and anchors
The frame PNG is a complex shape: chamfered corners and notches at the top and bottom center. Define its usable inner area once, in `layout.config.ts`, as percentages of the frame image:
- `opening`: the inner screen rectangle (left, top, right, bottom in %), measured from the PNG at the edges of the inner bevel. The screen surface, texture, doors and content are clipped to it. If the opening has chamfered corners, use a `clip-path` polygon in % that matches the PNG.
- Anchors inside the opening, each with a margin in % of the opening:
  - **round counter + progress:** top-left
  - **timer:** top-right
  - **sample tooltip:** top-right, below the timer (or as set in the Figma frame)
  - **objective text:** bottom-center, attached to the bottom edge of the opening, clear of the bottom notch
- Font sizes inside the unit in `cqh`, derived from the Figma sizes at the reference frame height, so text keeps the same proportion to the frame at any size.

Add a debug toggle that outlines the opening, the anchors and the safe areas. The owner will use it to check the alignment against the frame art.

## 3. Game coordinates
- Keep a **reference coordinate system** for gameplay: the opening at its Figma reference size, in design px. Shape sizes from previous briefs (360 × 360, etc.) are in these units, so shapes scale together with the frame.
- Pointer → game coordinates goes through one function: viewport → inverse of `.unit`'s actual transform matrix → opening-local reference units. It replaces `toStageCoords`. Update its tests, including round 10's drop at several window sizes.
- Layout-dependent rounds (round 7's large rectangle, round 6's motion bounds, round 8's safe area) read the opening size from the new layout config.

## 4. Art and image pipeline
- Raw exports live in `assets-src/` (not committed). A script `npm run assets` uses `sharp` (pre-approved dev dependency) to write `public/assets/` as WebP, at 2× and 1× (plus AVIF if under budget), and a `manifest.ts` with each image's intrinsic size.
- Serve 1× or 2× with `srcset` based on device pixel ratio.
- A preloader loads every image in the manifest before the Ready screen and reports progress through events, for the v1.2 loading screen.
- Total download budget: about 4 MB at 2×. Report the final sizes.
