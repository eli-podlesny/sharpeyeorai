# Brief: v1.0a — Optical center, scoring, verdict, score screen

## Goal
Every round produces a fair, explainable score, and the game ends with a total out of 10,000, a verdict persona and a shareable result. Rounds still use the 200 × 200 rectangle. Round mechanics (timers, alerts, effects) are v1.0b, not this brief.

## 1. Optical center model (`src/rounds/opticalCenter.ts`)

All inputs and outputs in stage coordinates (design px). The shape may be rotated.

```
C  = area centroid of the shape                     (the "computed" center)
M  = pole of inaccessibility: the point inside the shape farthest from any edge
     (center of the largest inscribed circle)
B  = shape's axis-aligned bounding box in SCREEN space (after rotation)

Base = C + w × (M − C)                               w = skeletonWeight, default 0.35
O    = Base + ( −βx × B.width ,  −βy × B.height )    βy = 0.05 (up), βx = 0 (left; off by default)
if O falls outside the shape → O = M
```

Notes for implementation:
- For rectangles and other convex symmetric shapes M = C, so O is simply C moved up by 5% of the on-screen height (10px for the 200 × 200 square).
- The upward shift is applied in screen space, not along the shape's own axes: "up" is always up for the player, even when the shape is rotated.
- M: implement the Mapbox polylabel approach (quadtree search with signed distance), or add the `polylabel` npm package. That dependency is pre-approved. For `rect` shapes return C directly.
- `skeletonWeight`, `opticalBiasY`, `opticalBiasX` are global defaults in `game.config.ts`, overridable per round. Remove the old `opticalOffsetY` field and migrate.
- Unit tests: square (O = C − 10px in y), rotated rectangle (shift stays vertical on screen), an L-shape (C sits near the corner, M sits inside the thick arm, O lands between them and inside the shape), a shape where O would fall outside (falls back to M).

## 2. Scoring (`src/scoring/`)

Pure functions, fully unit-tested. Replace the "Scoring model" section of `CLAUDE.md` with this section once implemented.

Per round, for click P and latency t (ms):
```
dO = |P − O|            dC = |P − C|
accuracy  a = clamp(1 − dO / R, 0, 1) ^ k            R = falloffRadius = 0.5 × shorter side (100px), k = 1.5
speed     s = clamp(1 − (t − grace) / (max − grace), 0, 1)     grace = 1500ms, max = 8000ms
quality   q = a × (1 − timeWeight + timeWeight × s)            timeWeight = 0 for round 1, 0.2 for rounds 2–12
penalty   q = 0  (timeouts / system errors — v1.0b; keep the hook)
roundPts  = 10000 × q / roundCount                              (shown rounded to whole points)
total     = round(10000 × Σq / roundCount)                      max exactly 10,000
```
Reference values for the 200 × 200 square: 0px → 100% accuracy, 10px → 85%, 25px → 65%, 50px → 35%, 100px+ → 0.

Humanity lean (verdict only, never affects points):
```
sep = |O − C|
if sep < minSeparationPx (default 4) → round excluded from lean
t_lean = clamp( ((P − C) · (O − C)) / sep² , −0.5, 1.5 )        0 = machine-like, 1 = human-like
humanityIndex = mean t_lean over included rounds (null if none)
```

Session summary object (used by the score screen and later the leaderboard):
`{ total, rounds: [{ id, P, C, O, dO, dC, latencyMs, a, s, q, points, lean }], meanLatencyMs, humanityIndex, persona }`

## 3. Verdict personas (`src/scoring/persona.ts` + copy in `src/config/copy.ts`)

Tiers (thresholds in config):
- Accuracy tier by total: **sharp** ≥ 7500, **decent** 4500–7499, **blurry** < 4500
- Humanity tier by humanityIndex: **machine** < 0.35, **hybrid** 0.35–0.65, **human** > 0.65 (null → hybrid)
- Speed tier by mean latency of rounds 2–12: **fast** < 1500ms, **steady** 1500–4000ms, **slow** > 4000ms

Check overrides first, in this order:
1. **total ≥ 9800:** "Are you the algorithm?" / "We checked twice. You're not supposed to exist."
2. **fast + blurry:** "Click first, aim never." / "Impressive reflexes. Wrong planet."
3. **slow + sharp:** "The Sniper." / "Took your sweet time. Didn't miss. Terrifying."

Otherwise accuracy × humanity (headline / line):

| | machine | hybrid | human |
|---|---|---|---|
| **sharp** | A human with a robotic vision. / You spend too much time in front of the laptop. Go outside and touch the grass. | Calibrated. / Half designer, half firmware. Both halves are annoyingly good. | The Eye. / No ruler. No grid. No doubt. Art directors would kill for your instincts. |
| **decent** | Budget android. / You think in pixels, but the pixels don't think back. Software update recommended. | Suspiciously average. / Not human enough to trust. Not machine enough to replace. Yet. | Gut feeling, mostly. / Your eye knows where the center is. Your hand is still negotiating. |
| **blurry** | Broken calibration. / You aimed like a machine and missed like one too. Have you tried turning yourself off and on again? | Glitch in the system. / We reviewed your data. We're not sure what you are. Neither are you. | Very, very human. / The center is a social construct, apparently. Please don't hang pictures at home. |

Speed tag, shown as a third, smaller line (not shown when an override fired):
- **fast:** "Speedy Gonzales. You clicked before the shape finished loading."
- **steady:** "Steady hands. The machine respects that."
- **slow:** "Slowpoke. The test is over. You can stop measuring now."

All persona text lives in `copy.ts`, so the owner can edit it without touching logic.

## 4. Score screen (plain, styled properly in v1.1)

Following the Figma "Score" frame:
- "Your medical summary" label, the total as `7412pts` (hazard orange, counted up from 0 over ~1.2s), the persona headline, the line, the speed tag.
- **Details** toggle: a 12-row table (round, offset from optical center, time, points), plus one diagram: the rectangle with all 12 clicks as numbered markers and the O point shown. Hovering a marker shows the sample tooltip (same component and style as the in-round "Sample 0X, logged" tooltip), with round, x, y, time and points.
- **Share result:** copies `I scored 7412/10000 on SharpEyeOrAI — "A human with a robotic vision." sharpeyeorai.vercel.app` to the clipboard, then shows the same tooltip component next to the button reading "Copied". If clipboard access fails, the tooltip shows the text so it can be copied by hand.
- **Play again** returns to `ready`.
- The tooltip is a single reusable component in `src/ui/tooltip.ts`; the in-round tooltip must be migrated to it.

## 5. In-round sample tooltip
Keep the existing behavior, now using the shared tooltip component. It shows x, y, time and "logged". No points shown during the game: the score stays hidden until the end.

## 6. Debug panel additions
- Show O, C and M markers (toggle), and the live dO / dC / q values under the cursor.
- "Autoplay" button: plays all 12 rounds with clicks drawn from a configurable spread around O, so the owner can check the score screen and every persona quickly. Include presets that land in each persona and override.
